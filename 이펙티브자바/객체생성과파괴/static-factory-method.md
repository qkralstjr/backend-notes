# 아이템 1. 생성자 대신 정적 팩터리 메서드를 고려하라

> **정적 팩터리 메서드** : 클래스의 인스턴스를 반환하는 클래스 내부의 static 메서드

## 장점

### 1. 이름을 가질수 있다

- new 생성자 사용하면 생성자 이름이 고정되고, 파라미터가 여러개일때 어떤 의미의 객체인지 알기 어려움 (내부 봐야함)
- 하나의 시그니처로 생성자 하나만 만들수있음
  ```java
  public Coupon(String name, int amount) { ... } // 정액 할인 쿠폰 (3000원 할인)
  public Coupon(String name, int rate) { ... }   // 정률 할인 쿠폰 (10% 할인) → 컴파일 에러 (시그니처 중복)

  new Coupon("신규가입", 10); // 10원 할인인지 10% 할인인지 호출하는 쪽에선 알수없음
  ```
  ```java
  // 정적 팩터리 메서드로 바꾸면 이름으로 구분 가능
  public static Coupon fixedAmount(String name, int amount) { ... }
  public static Coupon percentage(String name, int rate) { ... }

  Coupon.fixedAmount("신규가입", 3000);
  Coupon.percentage("신규가입", 10);
  ```
- 정적 팩터리 메서드는 메서드 명으로 객체 특성을 파악할수 있고, 시그니처가 같은 생성자가 여러개 필요할때 이름이 다른 정적 팩터리 메서드 여러개로 구분 가능

### 2. 호출될때마다 인스턴스를 새로 생성하지 않아도됨

- new 생성자는 호출될때마다 메모리에 객체 생성을 하지만, 정적 팩터리 메서드는 기존 객체를 반환하는 방식으로 재사용 가능
- 같은 객체가 자주 요청되는 상황일때 성능 이점이 있다 (플라이웨이트 패턴과 비슷한 기법)
- 인스턴스를 통제할수 있어서 싱글턴(아이템 3), 인스턴스화 불가(아이템 4) 클래스로 만들수있음

> ❗️ 같은 정적 팩터리 메서드를 여러 곳에서 호출해 같은 객체를 받은 상태에서 한 곳이 값 변경하면 다른 곳도 영향받음.
> 그래서 재사용하려면 불변객체여야 안전함

### 3. 반환 타입의 하위 타입 객체 반환이 가능

- 반환 타입을 인터페이스로 두면 구현 클래스를 public으로 공개 안해도 됨
- → API가 작아지고 클라이언트는 인터페이스만 알면 됨
- ex) `Collections.unmodifiableList()` 반환 타입은 `List`지만 실제로는 숨겨진 구현 클래스 반환

### 4. 입력 매개변수에 따라 매번 다른 클래스의 객체를 반환할수있음

- ex) `EnumSet`은 원소 64개 이하면 `RegularEnumSet`, 65개 이상이면 `JumboEnumSet` 반환 (클라이언트는 몰라도 됨)

### 5. 정적 팩터리 메서드 작성하는 시점에 반환 객체의 클래스가 존재하지 않아도 된다

- 반환 타입이 인터페이스라서 가능. 서비스 제공자 프레임워크의 기반
- ex) JDBC `DriverManager.getConnection()`은 나중에 만들어진 MySQL 드라이버의 클래스를 반환

## 단점

### 1. 정적 팩터리 메서드만 제공하면(public/protected 생성자 없으면) 하위 클래스를 만들수 없음

- 대신 상속보다 컴포지션을 사용하도록 유도하니 오히려 장점이 될수도 있음

### 2. 프로그래머가 찾기 어려움

- api 설명(문서)나 메서드명으로 정확히 알수있도록 작성
- 명명 규칙 : `from`, `of`, `valueOf`, `getInstance`, `newInstance` 등
